# origin-distribute

将 origin（xiaolin-life 站点）的内容**忠实适配**为社媒分发版本。**忠实**意味着：origin 的核心信息（数据、结论、立场）100% 保留；**适配**意味着：表达形式按平台规则压缩、重组。

**核心立场**：origin 是创作源，分发版是出口。**禁止重新创作**——这会导致数据漂移、立场偏移、SEO 重复内容惩罚。

---

## 何时使用

| 触发话术 | 场景 |
| --- | --- |
| 「把这篇同步到小红书」 | 单平台分发 |
| 「为 X 生成小红书推文」 | 单文章→单平台 |
| 「分发到社媒」 | 多平台分发（v1 仍只生成小红书，标记其他平台为 TODO） |
| 「xhs 版本」/「推文版」 | 简写触发 |
| 「origin 怎么适配」 | 询问工作流 |

**不应使用**：

- 用户原创社媒内容（origin 不存在）→ 走通用写作
- 仅修改单张图或单段文案 → 用 Edit 工具，不走 skill

## 工作流（小红书 v1）

### 步骤 1：定位 origin

从对话或路径中识别 origin 文章：

- `content/<区>/<slug>/index.md`（生活/思考/电影等）
- `content/drinkzen/<brand>/<drink-slug>/index.md`（饮品测评）
- 任意 Page Bundle 结构

**如果 origin 不存在**：先停，问用户 origin 在哪。

### 步骤 2：抽取关键事实

从 origin 抽取以下要素，**逐项标记原文位置**（便于追溯）：

| 字段 | 来源 |
| --- | --- |
| 品牌 / 品类 | frontmatter `title` / `summary` |
| 核心数据（热量/糖/咖啡因/评级） | 营养计算章节 |
| 一句话评价 | `## 口感体验` 或 `## 一句话` |
| 推荐点单 | `## 饮用建议` |
| 限定/热点（如有） | frontmatter `tags` 或首段 |
| 配图清单 | `gallery/` 目录 + carousel 配置 |

**忠诚度原则**：所有数据必须 1:1 来自 origin，不许补、不许改。

### 步骤 3：套模板

读取 `references/xiaohongshu-template.md`（小红书 v1 模板），按下列章节生成：

1. 标题（4 选 1 公式，参考 `references/title-formulas.md`）
2. **正文（100-300 字主流区间；结构：数据钩子 + 个人体验 + 知识科普 + 行动建议 + 一句话）**
3. 4-6 张图清单（来自 origin gallery，按模板角色映射）
4. 标签三档（必带 3 + 栏目 2 + 流量 3-5）
5. 评论区置顶（3 行：🥤 + 📍 + 💡）

**覆盖完整**：origin 的所有关键事实必须出现在分发版的某处。

**正文长度演进**：

- 早期 v1：≤80 字 4 行结构（数据钩子为主）—— **已过时**
- 当前主流：100-300 字（数据 + 体验 + 知识 + 建议）
- 原因：小红书分发版定位「知识 + 分享」，纯数据笔记打开率低于体验型笔记

**正文扩展素材来源**（仅 origin 内）：

| origin 章节 | 可压缩为分发版 |
| --- | --- |
| `## 口感体验` | "前调 / 中段 / 尾调"个人体验 |
| `## 饮用建议` | "最佳温度 / 适宜场景 / 不建议" |
| `## Nutri-Grade 评级` / `## 配方营养计算` | "为什么 C 级"知识科普 |
| `## 参数叠加汇总` | "加糖 / 加奶"行动建议 |

**禁止凭空扩展**：未在 origin 出现的卖点（如估算的咖啡因数据）不得添加。

### 步骤 4：输出

**A. 落盘 staging 目录**：

```html
content/social-publish/drafts/
└── <origin-slug>-xhs.md
```

frontmatter 引用 origin 路径，保留可追溯性。

**B. 纯文本展示**：在对话中输出一个 markdown 代码块，标注「可复制到小红书 APP」。

### 步骤 5：可选 commit（**必须用户明确指令**）

按项目 Git 规则，**不自动 commit**。用户确认草稿后再执行 `git add` + `git commit`。

## 设计原则

### 1. 忠实优先，可压缩不可扩展

origin 是「Source of Truth」。可以**压缩**（如 1000 字 → 80 字），但**禁止扩展**（如补 origin 没有的口播描述、加 origin 没说的卖点）。扩展会导致社媒用户来到站点后看到「不是这篇」，影响信任。

### 2. 重叠是常态，不是 bug

origin 与小红书**大量重叠**是正常的。SEO 视角下，origin 是 canonical URL，社媒是外链引用源。重叠反而强化品牌一致感。

### 3. 平台是形式过滤器，不是内容生成器

小红书要封面杀手、4-6 图、≤80 字正文——这些是**形式约束**。遇到 origin 信息无法塞进 80 字时，**优先压缩结论**（如「提神抗饿，好喝」），**不要新增修饰语**。

### 4. 数据是硬约束

热量、糖、咖啡因、ABCD 评级**禁止改动**。如果模板放不下，**先压缩修饰语**再压缩数字。数字改了就是失实。

### 5. 落盘不替代发布

`drafts/` 是发布**前**的中间态，不是发布记录。发布后的状态变更（点赞、评论、加微）由人工在小红书 APP 维护，不进 git。

---

## 减法原则

新规则/新模板进来时三问：

1. 不加这条，损失什么？——若答案是「更通用」，多半不需要
2. 这条能否合并进已有章节？——平台越多，模板越要分形而非平铺
3. 这条执行是否超过 1 分钟？——超过即拆分
