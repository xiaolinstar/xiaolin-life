## v2.2 铁律（小红书 text 专项）

| 铁律 | 说明 | 反例 → 正例 |
|------|------|------------|
| **无内部链接** | 禁止 `[text](/drinkzen/...)` `[text](url)` 等任何带 URL 的 markdown 链接 | ❌ 「[拿铁](/drinkzen/luckincoffee/latte/)」 → ✅ 「拿铁」 |
| **无感叹号** | 禁止 `！` `!`（含半角全角） | ❌ 「必须搅匀再喝！」 → ✅ 「必须搅匀再喝。」 |
| **无 markdown 列表** | 禁止 `-` `*` `+` `1.` 开头（包括行内「•」「·」开头的伪装） | ❌ 「- 第一步」/「1. 第一步」 → ✅ 「第一步，...」 |
| **无 markdown 加粗** | 禁止粘贴框内出现 `**text**` 语法；加粗粘到小红书会变成字面字符 `**`，AI 生成感强 | ❌ 「**仍 C 级**」 → ✅ 「仍 C 级」 |
| **≤ 800 字符** | 上限 800，红线 1000（小红书统计字符含中英数 emoji） | 主流区间 600-800 |
| **活人感** | 体感段必须像朋友发微信，不用结构化分层 | ❌「前调 / 中段 / 尾调」 → ✅「第一口别急着喝...」 |
| **不补博主实测** | origin 的博主实测数据默认不进入小红书（除非有官方背书） | ❌ 「博主实测 129 kcal」 → 删 |
| **正文不含 meta 说明** | 给分发者的注释（如「（直接粘贴，不带任何内部链接）」「→ 直接 copy」等）不进粘贴框 | ❌ 「进阶对比（直接粘贴，不带任何内部链接）：」 → ✅ 「进阶对比：」 |
| **段落尾部无句号** | 每个段落最后一句结尾不写句号（段中分句句号保留） | ❌ 「...外卖不建议。」 → ✅ 「...外卖不建议」 |

**为什么这些铁律**：小红书 text 字段是「直接粘贴发布」的纯文本字符串，不像 origin 站点那样渲染 markdown。所有站点内部链接 / 标记语法粘过去都会变成字面字符，无法点击、降低阅读体验、甚至被平台降权。**粘贴框本质上是纯文本**，必须彻底清空所有 markdown 语法残留 —— 包括「无内部链接」「无感叹号」「无 markdown 列表」「无 markdown 加粗」等。核心判断：**粘到小红书是否会变成字面字符**、**AI 生成感是否强烈**。

## 章节结构（v2.3 修订：5 段，连续编号【1】→【5】，无缺口）

### 1. 标题

**长度**：≤ 20 字（小红书标题两行内显示完整）

**v2 公式**：`<卡路里>大卡 <评级> <风味钩子>`

| 模板 | 适用 origin |
| --- | --- |
| `431大卡 D 级警告，咸甜脆三重小心机` | 含 D 级 + 三重口感卖点 |
| `292大卡 C 级抹茶清新，液体奶酪咸香` | 含 C 级 + 抹茶/液体奶酪风味 |
| `197大卡 C 级桂米咖，三层香气递进` | 含 C 级 + 多层香气卖点 |

**v2 规则**：

- **禁止** 使用 `|` 分隔符（v1 风格，平台降权 + 阅读节奏差）
- **卡路里必须前置**（开头 ≤ 6 字内出现 `<数字>大卡`）
- **评级紧跟**（D 级 / C 级 / B 级 / A 级）
- **风味钩子**用抽象词（咸甜脆、清新、咸香、三层递进），避免直接点出产品全名
- 数字 / 字母 / 中文 / 全角标点 均按 1 字计，**空格不计**
- **禁止感叹号**（v2.2 新增）

**禁忌**：

- 不用 `|` `🔥🔥🔥` `震惊` `家人们` `姐妹们`
- 不用 `减肥` `瘦身` `掉秤` 等敏感词
- 不用第一人称数字（「我瘦了 5 斤」）—— 没有 origin 数据
- 不用 `！` `!` 等感叹号（v2.2 新增）

### 2. 正文（5 段结构，v2.3 连续编号【1】→【5】，无缺口）

**字数**：≤ 800 字符（v2.1 500-600 → v2.2 收紧到 ≤ 800，红线 1000）

**粘贴框纯文本说明**（v2.2 新增）：所有「给分发者」的 meta 注释（如「（直接粘贴，不带任何内部链接）」「→ 直接 copy」「→ 复制到小红书 APP」等）**不能**出现在粘贴框内。这些是给模板使用者的提示，不是给读者看的内容。

**结构化 vs 一段话**（v2.2 新增）：

| 章节 | 格式 | 原因 |
| --- | --- | --- |
| 【1】营养参数 | **emoji 分行 + 换行**（结构化） | 跨产品复用、数据密度高、便于扫读 |
| 【2】热量与评级 | 一段或分行 | 数据密度中等，热量与评级是 2 个独立维度 |
| 【3】制作配方 | 箭头链 `→`（一行内可换行） | N 层原料适合紧凑链 |
| 【4】口感体验 | **一段连贯口语化文字**（活人感） | 体感需要连贯叙事，分行会显得机械 |
| 【5】健康建议 | 一段或分行 | 警告条目适合结构化 |

**头部信息**（必含，3-5 行）：

```text
📍 今日饮品：<品牌>·<产品名>（大杯 <容量>ml / 超大杯 <容量>ml）
🔖 默认配置：<温度> / <糖度>（<配置约束>）
📅 上市：<日期>（<范围>，<同日上新其他产品>）
🎯 所属系列：<系列名>（<系列核心卖点>）
[<联名> / <酒精警告> / <关键限制> 等]
```

**5 段结构**（每篇必含，顺序固定，连续编号）：

#### 【1】营养参数 ⚠️ <口径>

**必含元素**：

- 热量（大杯为主，⚠️ 标注计算口径或官方口径）
- 糖（总糖 + 非乳源性糖分别披露）
- 蛋白质 / 脂肪 / 饱和脂肪
- 咖啡因 + **来源说明**（单源 / 双源）
- 杯量 + 冰块占比

**格式**：emoji 分行（热量 / 糖 / 蛋白脂肪 / 咖啡因 / 杯量）
**字数**：~120 字符
**v2.2 注意**：emoji 行内单独成行不算 markdown 列表（每行用 emoji 开头）
**v2.2 第二轮精简**：删超大杯警告 + 含纯牛奶过敏原警告（头部杯型规格信息可保留）

#### 【2】热量评级：<等级>

**必含元素**：

- 饱和脂肪 g/100ml + 等级
- 非乳源性糖 g/100ml + 等级
- 取较差项 → 最终等级
- **克重数据**：唯一降级方式的具体克重
- **热版对比**：热版饱和脂肪冲到多少（如果 origin 有数据）
- **vs 同系列对比**：与同系列其他产品的等级差异

**格式**：一段或分行（不要 markdown 列表）
**字数**：~80 字符

#### 【3】制作配方 · N 层叠加

**必含元素**：

- **完整 N 层原料清单**（含最后一步）
- 每个原料的克重 / 毫升
- 关键工艺说明（千目级 / 双窨制 / IIAC 金奖 / 1:8 打发等）
- **制作流程箭头链**（杯底→步骤1→步骤2→...→顶部，每一步都不能漏）

**格式**：用 `→` 箭头链连接各层，不要 `1. 2. 3.` 编号
**字数**：~130 字符

#### 【4】口感体验（v2.2 改为一段活人感描述）

**必含元素**：

- **连贯主观体验**（一段话，从开盖到喝完）
- **饮用方式提示**（先尝 / 搅拌 / 大口喝等具体动作）
- **关键感官对比**（冰 vs 热）
- **工艺让位说明**（短萃让位桂香等设计意图）

**格式**：**一段连贯口语化文字**，不用结构化分层、不用前调/中段/尾调
**字数**：~130 字符

#### 【5】健康建议 ⚠️

**必含元素**：

- 特殊人群（驾驶员 / 孕妇 / 酒精过敏者 / 控脂 / 控糖；含米酒/酒精警告作为法规要求保留）
- **饮用方式**（先尝 / 搅拌 / 顺序）
- **控糖说明**（最低糖度限制 / 唯一降级方式）

**格式**：一段或分行
**字数**：~70 字符
**v2.2 第二轮精简**：删过敏原具体到原料 + 杯型警告 + 进阶对比段
