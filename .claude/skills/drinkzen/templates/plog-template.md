## 数据抽取规则

- 只抽取 origin 有依据的事实；评级读取 [ratings.md](../references/ratings.md)，缺失处理读取 [search-guide.md](../references/search-guide.md)。
- 没有热量或评级时，标题改为饮品名/已知特点；不强行保持“数字 + 评级”。
- 不强制咖啡因、冰占比、原料克重、冰热对比或“唯一降级方式”。有相应证据才写。
- `date` 是文章日期，不直接抽成上市日。同日上新、限定回归、工艺认证分别核实。
- 原料顺序与实际制作步骤一致，不用 N 层标题诱导补出不存在的原料。
- “不另外加糖”不等于无糖；某个菜单选项不能保证降级，未提供的换奶不能推荐。
- 正文不提供孕妇相关建议，也不直接声称面向某类人群；围绕点单、风味和营养事实写，不给“安全”“随便喝”“不胖”等保证。
- 后台产品是否已存在、能否搜索须核实；未确认时省略产品搜索引导，不发布“待补门店”等占位内容。

## 文案约定

- 正文用 ```text 代码块包裹，方便直接复制发布；标签、评论区置顶同样用代码块。
- 标题用纯文本，不用代码块。
- 正文内不用 Markdown 链接或加粗；段落编号【1】-【4】保留（无点单提示段）。
- emoji 头部（📍🔖🔥🍬🥛⚠️）用于开头参数速览和【1】营养参数段内逐项标注；不含价格。
- 开头 emoji 速览后接 2-3 句总结（评级关键原因 + 一句话结论），再进入编号段落。
- 【3】制作配方用箭头连接原料（`冰块 100ml → 牛奶 225ml → 浓缩 30ml`），按制作顺序排列。
- 段间空一行，段内保留清晰换行；段末可省句号。
- 标签建议 8–10 个，保留 `#奶茶仙人 #DrinkZen`；全国连锁不自动加南京标签，地方限定或实际探店才加相应地域词。
- D 级可说明糖或饱和脂肪的实际原因，不自动生成控脂禁忌；含醇/过敏原提示仅基于证据，不作泛化医疗建议。
- 评论区置顶（不用"引流评论"）：包含小程序搜索引导 + 推荐点单 + 必要警告。

## 分发前自检

- [ ] 标题、正文、封面、引流评论与 origin 的同配置数值一致。
- [ ] 新加坡/上海标准与官方/估算性质明确，未知不当作 0。
- [ ] 点单选项来自同一个官方菜单项，没有把独立单品写成可替换选项。
- [ ] 没有未验证的原料克重、实饮体验、医疗保证或上市日期。
- [ ] 两平台共用同一内容，不另生成短版。
- [ ] 素材真实可用，后台搜索引导已核实，发布占位已清理。
- [ ] 发布后分别登记真实链接、时间和版本，内容更新后跟踪纠错。

检查用于提示事实和同步问题；是否设置自动发布门禁仍待定。
