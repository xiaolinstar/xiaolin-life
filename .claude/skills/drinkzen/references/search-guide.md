# DrinkZen 证据与缺失数据方案

## 证据记录

每个关键事实分别记录来源，不给整篇文章一个笼统的“官方”标签。

| 字段 | 内容 |
| --- | --- |
| 事实 | 热量、糖、饱和脂肪、咖啡因、原料、选项或价格 |
| 配置 | 品牌/菜单项/地区/杯型/冰度/糖度/基底/小料 |
| 来源类型 | 官方公开、第三方实测、配方估算、作者体验、未核实 |
| 来源定位 | 可追溯 URL、报告页码或本地菜单截图路径 |
| 时间 | 采集日期；上市日期另有证据才记录 |
| 数值与单位 | 原始值、每杯或每 100ml、是否含冰/小料 |
| 限制 | 样本地区、检测条件、缺失输入、与当前菜单的差别 |

截图母本可以保留在文章 `gallery/`，公开图片依媒体发布流程上传 COS；不能把本机未上传路径当成其他 Agent 可访问的证据。

## 来源的适用范围

- 菜单身份、选项和加价：优先当前品牌官方小程序；菜单截图要包含具体单品和地区/门店。
- 营养：优先同一配置的官方营养表/计算器；有明确方法和样本条件的检测报告可以引用，但不等同于品牌官方数据。
- 原料：配料表可确认原料种类，不能据此推出精确克重、泵量或制程。
- 消费者评价只能作为有出处的反馈；口感实饮由作者记录，不由 Agent 代喝。
- 来源冲突先检查规格、时间、地区和计量口径；仍不能解释时并列差异并标记待核实，不挑一个数字凑一致。

## 缺失处理

| 缺失项 | 处理 |
| --- | --- |
| 官方菜单或单品选项 | 标记待核实菜单，不生成虚构组合或加价 |
| 热量、咖啡因、糖或饱和脂肪 | 写未公开/待核实；plog 可省略该数值，不能填 0 |
| 乳糖/半乳糖或甜味剂情况 | 保留未知；不把全部碳水当糖，不把全部糖当乳糖扣除 |
| 配方克重或有效体积 | 不生成精确配方、每 100ml 数值和确定评级 |
| 口感实饮 | 写尚无实饮记录；有来源的反馈明确归属 |
| 上市日、价格、门店 | 无证据时省略，不用文章日期或行业均价代替 |

## 允许估算的条件

只有原料用量和营养依据都可追溯时，才计算配方估算值；注明假设、公式和区间。估算与检测结果分栏展示，不能倒推原料数据去强行匹配实测热量。

- 原料贡献 = 原料用量 × 对应每 100g/ml 营养值 ÷ 100。
- 每杯总值 = 各原料贡献相加；有效体积另有依据，杯容不自动等于液体量。
- 每 100ml = 每杯总值 ÷ 同口径有效体积 × 100；冰量和融化状态不明时不擅自换分母。
- 糖浆每泵/每勺用量、含糖量和能量都必须来自当前品牌资料；不得套固定 +5g/+20kcal。
- 若不确定区间跨评级边界，展示待核实或区间，不选择更好等级作为标题卖点。

## 内容一致性检查

逐项核对标题、产品速览、营养表、评级说明、plog、封面和评论的同一配置数值。保留“约”“估算”“待核实”等限定词；不能在分发时删除这些词来缩短标题。该检查用于发现问题，是否形成自动阻断门禁仍待定。
