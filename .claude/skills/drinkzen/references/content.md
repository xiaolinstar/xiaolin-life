# DrinkZen 内容创作

## 内容依据

饮品以品牌官方小程序中的菜单项为单位建页。品牌页用 [brand-template.md](../templates/brand-template.md)，单品页用 [drink-template.md](../templates/drink-template.md)。营养证据处理见 [search-guide.md](search-guide.md)，评级见 [ratings.md](ratings.md)。

## 菜单与页面映射

1. 记录品牌、官方产品全名、菜单项 ID（可取得时）、地区、门店和采集日期，以及截图或链接。
2. 原样记录该单品的选项组、可选值、默认值、单选/多选、加价及互斥关系。只记录可实际点选的组合。
3. 同一菜单项下的杯型、糖度、冰度、浓度等做本页规格；独立售卖的热/冰款或奶基底单品分别建页，不靠名称相似合并。
4. 品牌级菜单模板只是复用候选；单品没有的糖度、换奶、小料选项不能补入。售罄、下架与历史限定明确标记，不凭旧资料认定在售。
5. 对照 DrinkZen 产品 ID 和菜单配置。无法读取后台产品时，在台账保留“待关联”，不假定已经同步。

已有页面保留稳定 slug；新页面采用已有品牌命名习惯（拼音或官方英文，全小写、连字符分词）。确需改名时保留旧地址 alias。不同品牌的同名饮品使用 `brand/slug` 区分。

## 默认配置

默认配置取自该菜单项实际默认选择，不统一假设大杯、冰或不另外加糖。推荐配置另列，并明确热量、评级对应哪一种配置。某选项不存在时写“菜单未提供”，不能把另一款饮品当作当前饮品的换配选项。

## 创作步骤

1. 核实菜单身份与选项，保存菜单证据。
2. 按证据等级填充已知营养值、原料和价格，未知字段保留未知；`date` 是文章日期，上市日期只有单独证据才能填写。
3. 默认采用新加坡评级；数据不足时写“待核实”，不因需要数字标题而补算。
4. 口感取自作者真实记录；没有记录时说明尚无实饮记录，可引用有出处的消费者反馈，不改写成亲历。
5. 在 origin 内生成一份共用 plog；登记台账并列出菜单、后台、内容与平台的待同步事项。

批量创建先列菜单映射清单，按品牌/系列处理；每篇核对菜单身份、选项、证据与缺失项，不能仅检查文件数量。是否并行执行按用户授权和任务规模决定。

## 更新与发布

模板只规定字段形态，不提供通用糖浆克重或固定营养数字。更改事实后同时检查正文、标题、表格、plog、封面和引流评论。平台已发布内容由 [运营闭环](operations.md) 跟踪修正。

Hugo `draft` 默认值与自动发布门禁暂沿用现状，待单独讨论；`draft: false` 不代表菜单、后台或社媒已经核实或发布。没有用户提交授权时不执行 Git 提交。
