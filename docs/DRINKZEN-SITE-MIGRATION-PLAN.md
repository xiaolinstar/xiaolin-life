# DrinkZen 内容复制与产品站建设计划

日期：2026-10-18。状态：修订后的方案与本地清单，尚未执行复制、数据导入或目标站发布。

## 1. 范围与目标

将 `xiaolin-life` 的饮品相关内容复制一份到 DrinkZen 仓库，作为 `drinkzen-site` 产品内容和运营资料的基础。原网站、饮品文章、原地址与编辑能力均保留，作者可继续独立运营。

目标站按 DrinkZen 产品任务组织：认识产品、查饮品、选规格、理解营养与评级、进入小程序记录和使用预算。页面定位与结构先按 [产品方案](DRINKZEN-SITE-PRODUCT-BRIEF.md) 做原型验证，再确定实施细节。

本计划中的“迁移”均指内容复制、审核和再加工，不表示旧站退役。本站删除、停止编辑、旧 URL 重定向、原站 canonical 变更和 SEO 权重转移均不属于本次范围。

## 2. 两站与数据的分工

| 载体 | 定位与职责 |
| --- | --- |
| xiaolin-life | 原网站及饮品文章保留，继续承载作者表达与个人运营 |
| drinkzen-site | DrinkZen 公开产品站，围绕查询、规格、营养解释与小程序入口组织内容 |
| DrinkZen Admin/API/PostgreSQL | DrinkZen 产品侧菜单、规格、营养、评级及来源的业务主存储 |
| DrinkZen 内部运营资料 | 来源档案、共用 plog、素材、发布与纠错记录 |

目标站沿用现有 `drinkzen/apps/site`、Nuxt SSR、公共 API 与 K8s 基础。产品数据通过 Admin/API 维护，不执行 seed 导入；博客文件是来源资料，不自动覆盖数据库。

复制后两站各自有编辑入口，不强制双向同步。首次复制记录来源和版本，后续源文变更可提醒人工复核；目标站重新加工过的内容不会被源文覆盖，目标站的改动也不自动回写博客。

## 3. 现有资料基线

本地盘点共 243 个 Markdown：220 个单品页、20 个品牌栏目、1 个总入口、2 个说明/运营页；其中 117 个 draft、126 个非 draft。

另有 5 份菜单 JSON、3 份营养 JSON、12 篇含 plog 的文章。本地台账有 1 条菜单证据记录，未登记产品关联和平台发布事件。其中 Manner Latte 营养 JSON 尚未跟踪，需要明确纳入本次来源快照。

清单见 [inventory.csv](drinkzen-site-migration/inventory.csv) 和 [字段说明](drinkzen-site-migration/README.md)。13 条旧别名保存在 [aliases.csv](drinkzen-site-migration/aliases.csv)，仅用于来源追溯，不是重定向任务。

盘点只代表本地资料存在，不代表来源已核实、后台已有产品或社媒已发布。原草稿可复制到内部档案，不能因此自动公开。

## 4. 产品站先行设计

### 4.1 首版页面

| 模块 | 产品任务 | 首版建议 |
| --- | --- | --- |
| 首页 | 认识 DrinkZen、开始查询、找到小程序 | 产品价值 + 搜索 + 真实案例 + 使用入口 |
| 饮品库 | 按名称、品牌、单杯热量与明确标准的评级找饮品 | 复用并完善现有查询，不按文章发布日期浏览 |
| 产品详情 | 看清具体菜单项与规格的营养和来源 | API 数据卡片 + 选项/规格 + 简洁提示 + 可展开解释 |
| 品牌目录 | 找到品牌与菜单 | 简洁品牌入口与产品列表 |
| 使用帮助 | 学会查询和使用小程序 | 围绕操作任务，连接实际能力 |
| 数据与评级 | 看懂标准、估算、未知与来源 | 新加坡默认、上海可选，明确解释口径 |

原文长内容可以形成可展开的资料说明、真实体验模块或指南，前台结构不直接复制 Hugo 的文章、分类、归档与 plog tab。

### 4.2 原型验收

先制作首页、饮品库和一个产品详情的可交互原型，再确认功能和视觉。使用真实样本验证：能找到饮品、选择真实配置、看懂对应数据及限制、找到小程序入口。

原型阶段核对小程序现有能力、入口方式与具体目标域名；暂按 `https://drinkzen.cn` 规划，不把尚未验证的跳转或个人预算同步写成现成能力。

原型确认前，可做内部资料复制与核对；批量公开页面加工等待结构稳定，避免先把博客全文上线再返工。

## 5. 内容复制与加工方式

### 5.1 完整保留来源，按需公开

先复制饮品相关 Markdown、menu/nutrition JSON、共用 plog 和必要素材引用到目标仓库内部来源档案，保留路径、文件摘要、源提交与复制时间。博客原文件及 Git 历史保持完整。

本地 gallery 被忽略的媒体需单独盘点、备份和传输，不能只复制 Git 跟踪文件。现有 COS/CDN URL 继续使用，不在本轮更换媒体域名或对象键。内部截图和资料不自动公开。

目标目录草案（待原型与契约确认，当前尚未创建）：

```text
drinkzen/
  operations/sources/xiaolin-life/<batch_id>/
  operations/copy-manifest.csv
  operations/content/<content_id>/plog.md
  operations/content/<content_id>/assets.json
  operations/publications.json
  apps/site/content/products/<content_id>/
  apps/site/content/help/
```

`operations/` 不进入公开静态目录或路由。来源档案保留复制时原貌，业务事实仍通过 Admin/API 核实；不把来源快照当 seed 或第二份实时主库。

### 5.2 从文章转为产品信息

| 来源内容 | 加工结果 |
| --- | --- |
| 产品名、默认配置、菜单选项 | 与官方菜单及后台 ID 核对后的产品/规格信息 |
| 营养表和评级 | 检查口径、来源、估算与状态后录入或关联 API，公开页展示产品数据 |
| 点单提示 | 产品页可读的配置差异与已确认事实 |
| 配方与长篇分析 | 注明假设和版本的可展开解释，不强制逐篇长文上线 |
| 真实口感与配图 | 可选体验模块，注明作者和来源 |
| 科普与对照 | 数据说明、帮助或产品相关指南 |
| plog、运营排期、模板 | 内部运营资产，不放在公开饮品详情末尾 |

一篇原文可拆为多个模块，多篇原文也可支持同一个产品或帮助主题。不要求 243 个源文件对应 243 个目标公开页面。

### 5.3 数据与内容边界

- 产品和规格用后台真实 ID 关联；相同名称或 slug 不足以自动合并，官方小程序菜单项是识别依据。
- 新加坡默认、上海可选，显示标准名称与性质；不静默回退到另一标准或旧热量分档。
- 官方值、第三方检测与配方估算分开记录。估算保留输入、模型和限制，资料不足标未知，不因复制升级为 verified。
- 没有作者确认的实饮体验不转为亲历；不提供孕妇建议、目标人群限定或安全保证。
- 保留原发布日期、源状态和来源路径；目标公开状态单独审批，不将复制时间当上市或实饮时间。

## 6. 来源与后续更新

每个目标模块记录稳定 content_id、原文件/URL、源提交、复制批次、源文件摘要、实际产品/规格 ID、目标内容版本与公开状态。

| 变化 | 处理 |
| --- | --- |
| 博客原文更新 | 可生成差异提示，由运营决定是否吸收；不自动覆盖目标站 |
| DrinkZen 数据更新 | 更新 API 展示，检查目标解释内容及 plog；博客原文可单独决定是否修订 |
| 目标站重新编辑 | 更新其独立内容版本，不回写博客 |
| 原草稿转为公开 | 两站分别决定发布，互不推断 |
| 正文、营养或素材变化 | 对已发布的目标站及社媒生成跟进事项；完成线上修正后再登记 |

共用 plog 只维护一份平台文案，小红书与大众点评分别保存真实链接、时间、采用的数据/文案/素材版本和效果记录。原有 history/metrics 复制时保留，不因出现第二个站点重复生成发布事件。

运营台账应绑定稳定 content_id；在内容再加工后，将后续实际发布记录关联到其使用的文案版本。内部版本检测覆盖 API 数据、正文、素材及共用文案，不只检查 Markdown。

目标站公开内容以产品模块重新组织，保留适当来源关系。原站地址、索引与 canonical 保持现状；若未来确需全文转载及特殊 canonical 策略，针对具体页面另行讨论，不默认调整原站。

## 7. 实施阶段与产出

估计为单人有效工作量，取证、原型讨论和数据库核对可能延长日历时间。

| 阶段 | 主要工作 | 产出与完成条件 |
| --- | --- | --- |
| A：产品定义与原型，2–3 天起 | 确认用户任务、页面结构、规格交互、来源表达与小程序入口 | 首页、饮品库、产品详情原型通过任务验证 |
| B：来源复制与关联，1–2 天起 | 保存源快照、复制资料与媒体引用、核对产品 ID、标记资料问题 | 文件摘要匹配、博客未改动、草稿未公开、映射可追溯 |
| C：目标站 MVP，3–5 天起 | 实现确认的页面、内容模块、数据展示、内部文案/台账适配 | SSR/移动端/错误状态及数据口径正确，内部资料不公开 |
| D：样板验证，2–3 天起 | 3 款饮品与评级说明，验证查询、配置、解释、入口和纠错 | 样板可用，复制/发布事实有记录，无重复后台条目 |
| E：持续内容加工 | 按产品任务与运营需要处理其余来源资料 | 经复核的模块逐批公开，两站均可独立运行 |

A 与 B 的内部盘点可并行安排，批量公开内容等待 A 稳定；不以完成全部历史文章为 MVP 上线条件。

### 7.1 目标站实施前要补齐

- 公共 API 不暴露草稿查询；内部预览不进入公开路由、sitemap 或静态产物。
- 产品详情展示当前选中规格的数据；没有营养值的组合标待完善，不沿用另一杯配置。
- 下架、未知、在售状态可辨；需要保留历史详情时先统一列表和详情 API 的可见性。
- 去除评级静默回退与“A 级放心喝”；数据不存在、上游故障分开处理，不把临时故障都变成 404。
- 查询与筛选覆盖实际结果集，不能只过滤前 500 条；新增 canonical/sitemap 按目标站自己的产品路由实现。
- 使用实际 0.6.0 product/variant 能力核对 CLI 环境和写后读回；修正 Skill 中不存在的 sync/verify 命令。

### 7.2 样板候选

| 候选 | 需要验证 |
| --- | --- |
| Manner 冰拿铁 | 真实菜单选项、浓度与规格营养、源公开文章的再加工 |
| 瑞幸咸芝士豆乳拿铁 | 既有菜单台账、来源状态、原 draft 不自动公开 |
| 瑞幸埃塞金烘拿铁 | 多产品对照、原 draft 与历史别名追溯 |
| 新加坡/上海评级说明 | 标准名称、默认/可选、估算和未知的表达 |

先核实候选资料和真实产品 ID，不保证已有营养计算或体验可直接使用。至少完成一次数据变化和一次文案/素材变化的纠错演练，确认不会覆盖博客或重复创建产品。

## 8. Skill 与运营流程

目标站结构确认后，在 DrinkZen 仓库增加面向产品内容加工的 Skill，复用 CLI 自带手册；本站既有 Skill 保留并明确自身负责博客创作，两者按路径与任务路由，不相互覆盖。

两边共用的评级与证据原则指定一个维护来源并记录引用版本；路径、模板、文案风格和页面结构按各自站点调整。先修正强制猜配方、代写实饮和台账示例等冲突，不机械复制错误规则。

资料复制完成后，博客仍可继续新增和修改饮品文章；如需将新资料继续复用到产品站，通过后续复制批次和差异复核处理。本站不承担目标站的强制同步或退役任务。

## 9. 验收、发布与回滚

### 验收

- [ ] 复制范围、源提交、工作区文件与批次明确，未跟踪资料已单独记录。
- [ ] 源内容与媒体引用完整可追溯，博客原文件、地址、导航和发布配置未被修改。
- [ ] 内部档案与原草稿没有自动变为公开页面。
- [ ] 目标结构按产品任务组织，正文中无遗留 Hugo shortcode、编辑操作或 plog 工作台。
- [ ] 产品/规格 ID、当前配置和营养口径一致；估算与来源状态正确。
- [ ] 两套标准明确，未知不补 0，不以安全保证作宣传。
- [ ] 首次查询、选规格、理解数据和小程序入口路径可用；未接入能力不作上线宣传。
- [ ] 目标站相关 typecheck/build、API/CLI 与 SSR/错误状态检查通过。
- [ ] 版本变更、发布记录和纠错可追溯，既有社媒历史无重复事件。
- [ ] 目标站上一版镜像、内容快照、业务字段变更与补偿措施可定位。

### 发布与回滚

目标站先预览、验收再分批发布。发布和回滚只涉及目标站新增模块及明确的业务数据变更；本站继续服务，不参与切流。

目标站故障时恢复前一版镜像或撤下本批新内容；Admin/API 导入按实际字段变更做补偿，不整库恢复覆盖用户新记录。保留来源档案、真实社媒链接与历史观测，便于修复后继续。

不执行旧 URL 301、删除博客、强制停止编辑、移动 COS 对象、seed 回流或社媒自动发布。跨站入口推荐可在双方页面成熟后单独添加，不是复制的前置条件。
